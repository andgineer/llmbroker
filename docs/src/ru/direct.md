# Прямые вызовы модели

Методы `ask`, `chat` и `stream` выбирают модель из пула и при ошибке переходят к
следующей. Если нужно обратиться к **одной конкретной модели**, используйте
`broker.direct(...)`. Такой вызов выполняется напрямую, без выбора из пула и без
автоматического перехода к другой модели.

Для прямого доступа модель нужно указать в параметре `direct=` при создании
брокера. К моделям из пула обращаются только через `ask`, `chat` или `stream`.
При попытке передать имя модели из пула в `direct()` возникнет `PoolModelError`.

## Настройка и вызов

```python
broker = llmbroker.Broker(direct=["opus"])
broker.direct("opus").ask("...")
```

`"opus"` — постоянный псевдоним из поддерживаемого каталога платных моделей. При
выходе нового поколения Claude каталог может связать `opus` с новой версией, при
этом код приложения менять не потребуется. Псевдоним не содержит номера версии
и не переименовывается. Нужный API-ключ определяется провайдером, например
`ANTHROPIC_API_KEY` или `OPENAI_API_KEY`.

Список моделей из `direct=` не записывается в реестр: его источником остаётся код
приложения. Соответствие псевдонима конкретной версии проверяется примерно раз в
сутки вместе с обновлением пула. Отдельная синхронизация или локальный файл для
этого не нужны.

Если каталог недоступен во время проверки, брокер продолжает использовать уже
выбранную версию и записывает предупреждение в журнал. Ранее найденное
соответствие не заменяется более старым. Ошибка возникает только при первом
разрешении псевдонима, например если в нём есть опечатка; сообщение перечислит
доступные варианты.

## Собственная конфигурация модели

Вместо псевдонима можно передать `LLMConfig`. Это подходит для модели на
собственном сервере, корпоративного шлюза или версии, которую нельзя обновлять
автоматически:

```python
from llmbroker import LLMConfig

gateway = LLMConfig(
    name="frontier",
    model="claude-opus-4-8",
    base_url="https://api.anthropic.com/v1",   # любой API, совместимый с OpenAI
    api_key_ref="ANTHROPIC_API_KEY",
)
broker = llmbroker.Broker(direct=[gateway])
broker.direct(name="frontier").ask("...")
```

Такая конфигурация, включая версию модели, не изменяется при обновлении каталога.

## Прямые модели не входят в пул

Модель из `direct=` никогда не участвует в выборе моделей, не используется как
запасная и не учитывается в `count()` и `snapshot()`. Пул предназначен для
взаимозаменяемых бесплатных моделей с общей логикой ограничений. Прямые модели и
частные шлюзы управляются отдельно.

Собственную модель можно включить в пул, если [добавить её в реестр
самостоятельно](server.md#own-entry). Автоматическое обновление такую запись не
изменит. Реестр содержит только модели пула, поэтому добавление в реестр и
объявление через `direct=` — два разных способа использования модели.

## Как найти платную модель

Команда `llmbroker list` показывает поддерживаемые бесплатные и платные модели и
ничего не изменяет. В строке `direct` сначала указан псевдоним для `direct=`, а
затем идентификаторы провайдера и модели, `base_url` и `api_key_ref`:

```
$ llmbroker list
pool groq-gpt-oss-120b openai/gpt-oss-120b https://api.groq.com/openai/v1 GROQ_API_KEY
...
direct opus anthropic claude-opus-5 https://api.anthropic.com/v1 ANTHROPIC_API_KEY
direct sonnet anthropic claude-sonnet-5 https://api.anthropic.com/v1 ANTHROPIC_API_KEY
```

## Чтение каталога из программы {#curated}

Те же данные можно прочитать из программы без создания брокера. Сначала
используется сохранённая локальная копия, а при её отсутствии — копия из
установленного пакета. Доступ к сети для этих функций не требуется:

```python
from llmbroker import curated_paid, curated_pool, curated_providers

for row in curated_paid():
    print(row.alias or "-", row.name, row.label)

for provider in curated_providers():
    print(provider.id, provider.base_url, provider.api_key_ref)

print(len(curated_pool().configs), "бесплатных моделей в поддерживаемом списке")
```

Через описание провайдера можно настроить и модель, которой ещё нет в каталоге,
например недавно выпущенную версию. Создайте конфигурацию методом `declare()` и
передайте её в `direct=`:

```python
anthropic = next(p for p in curated_providers() if p.id == "anthropic")
broker = llmbroker.Broker(direct=[anthropic.declare("claude-opus-9-preview")])
broker.direct(name="anthropic-claude-opus-9-preview").ask("...")
```

`declare()` подставляет адрес API и имя ключа. Результатом становится полная
конфигурация с фиксированной версией, которая не обновляется вместе с каталогом.
Метод `.declare()` есть и у записей каталога; он также фиксирует текущий
идентификатор модели. Чтобы автоматически переходить на новые версии, передайте
в `direct=` строковый псевдоним.

Эти функции только читают данные. Обновление выполняет `sync`. Поведение при
отсутствующем ключе описано в разделе [Ошибки](#errors).

## Различие между `alias` и `name`

Псевдонимы и полные имена обрабатываются отдельно. Параметр `name=` можно
использовать для проверки версии: если указать `anthropic-claude-opus-5`, а
псевдоним в каталоге уже соответствует другой версии, вызов завершится ошибкой,
а не перейдёт на новую модель незаметно.

Конфигурации из `direct=` не сохраняются в реестре. Значения ключей также не
сохраняются: во время вызова они читаются из переменных окружения или выбранного
хранилища секретов.

## Обновление модели, заданной псевдонимом

Соответствие псевдонима конкретной версии проверяется примерно раз в сутки вместе
с обновлением пула. При переходе на новую версию в журнал записываются прежнее и
новое значения:

```
direct=: opus: claude-opus-4-8 -> claude-opus-5
```

После обновления поле `name` содержит новую версию. Если изменился провайдер, в
записи также будет новый `api_key_ref`. Перед следующим вызовом задайте
соответствующую переменную окружения.

Полная конфигурация `LLMConfig` не обновляется, поскольку она не связана с записью
каталога.

## Асинхронные вызовы и потоковая выдача {#streaming}

```python
async with llmbroker.AsyncBroker(direct=["opus"]) as broker:
    client = await broker.direct("opus")

    # потоковая выдача через асинхронный итератор
    async for delta in client.stream("Напиши хокку про брокеров"):
        print(delta, end="", flush=True)

    # либо весь ответ сразу
    result = await client.ask("Дай полный текст")
    print(result.text, result.usage)
```

Прямой вызов обращается к одной указанной модели. Брокер не выбирает модель из
пула, не переходит к другой при ошибке и не записывает вызов в журнал. Потоковая
выдача из пула описана в разделе
[Асинхронные вызовы](async.md#streaming-from-the-pool).

## Синхронно

Синхронный `Broker` также предоставляет `direct(...)`, но поддерживает только
`ask()`. Для потоковой выдачи нужен `AsyncBroker`.

```python
with llmbroker.Broker(direct=["opus"]) as broker:
    result = broker.direct("opus").ask("...")
    print(result.text)
```

## Параметры запроса {#params}

При прямом вызове можно передать параметры, поддерживаемые выбранной моделью,
например уровень рассуждения, температуру, ограничение числа токенов или `seed`.
Словарь `params` добавляется в тело запроса без изменений. Синхронный и
асинхронный клиенты принимают его в `ask()`, а асинхронный — также в `stream()`:

```python
client = broker.direct("opus")
client.ask("...", params={"reasoning_effort": "low", "temperature": 0})
```

llmbroker не проверяет и не изменяет значения из `params`. Если провайдер не
поддерживает параметр, его сообщение об ошибке передаётся приложению. Параметры
API провайдера помещаются внутрь `params`, а параметры llmbroker, например
`messages=` и `timeout=`, передаются отдельно.

Поля `model`, `messages`, `stream`, `stream_options` и `tools` формирует сам
llmbroker. Если одно из них передано в `params`, возникает `ValueError` с именем
поля. Это предотвращает замену выбранной модели и несовместимое изменение режима
ответа. Поле `tool_choice` разрешено, поэтому
`params={"tool_choice": "required"}` заменяет значение `"auto"`, которое
устанавливается вместе с `tools`.

`params` поддерживается только для прямых вызовов. Для пула доступны лишь
параметры, которые можно одинаково применить ко всем моделям. См. раздел
[Запрос JSON по схеме](usage.md#response-format).

## Ошибки {#errors}

Все исключения прямых вызовов наследуют `LLMRequestError`:

- `PoolModelError` — указано имя модели из поддерживаемого пула. Используйте
  `ask`, `chat` или `stream` либо создайте собственную конфигурацию модели.
- `UnknownModelError` — запись с таким именем или псевдонимом не найдена. Если
  значение существует в другой категории, это будет указано в сообщении. Та же
  ошибка возникает при запуске, если псевдонима из `direct=` нет в каталоге;
  сообщение перечислит доступные псевдонимы.
- `MissingKeyError` — не найден ключ из `api_key_ref`. Для прямого вызова это
  ошибка; модель пула без ключа просто не используется.
- `ProviderError` — провайдер вернул ошибку. Поля `.status` и `.detail` содержат
  код HTTP и фрагмент ответа. Для отдельной обработки можно перехватывать
  `AuthError` (401 или 403) и `RateLimitError` (429 или 503, с полем
  `.retry_after`).
- `InvalidProviderResponseError` — провайдер вернул HTTP 200, но тело не удалось
  разобрать как ответ модели либо в нём нет ни текста, ни вызовов инструментов.
  Поле `.model` содержит имя модели, а `.detail` — фрагмент ответа. При прямом
  вызове брокер не может перейти к другой модели, поэтому исключение передаётся
  приложению.
- `LLMTimeoutError` — истекло время ожидания ответа.
- `StreamInterruptedError` — потоковая выдача из пула прервалась после получения
  первых частей текста. Поле `.llm_name` содержит имя модели, а исходная ошибка
  доступна в `__cause__`.
- `StreamReplacementError` — при потоковой выдаче из пула с `fastest_of > 1`
  другая модель завершила полный ответ раньше. Поле `.replacement` содержит этот
  ответ, а `.streamed_llm_name` — имя модели, чей предварительный текст нужно
  заменить.
