# CLI

Ничего из этого для работы с llmbroker не нужно — `Broker()` сам скачивает пул.
Две команды покрывают ровно то, чего llmbroker не может сделать за вас: получить
ключи провайдеров и показать, какие модели лежат в курируемых списках.

Обе работают офлайн: копия обоих курируемых списков вшита в пакет, поэтому машина
без сети откатывается на неё, а не падает. Эта копия заморожена на той версии
llmbroker, которую вы поставили, поэтому при её использовании команда сообщает об
этом в stderr.

## env — сформировать .env с ключами

```bash
llmbroker env freetier > .env
```

Печатает заготовку `.env` для названного курируемого списка моделей: над каждым
ключом — подсказка, где его получить:

```
# OPENROUTER_API_KEY — Create a free API key at [openrouter](https://openrouter.ai/keys).
OPENROUTER_API_KEY=
```

Имя пресета — это весь аргумент, поэтому команда одинаково работает и когда
локально ещё ничего нет, и когда реестр брокера живёт в базе. Имена, которые
можно назвать:

- `freetier` — бесплатные endpoints от Groq, OpenRouter и Gemini

Сами ключи получите у провайдеров и впишите. Брокер сам читает `.env` в рабочем
каталоге; переменная окружения всегда важнее его. Ключи вообще не обязаны лежать
в `.env` — см. [API-ключи](secrets.md).

## list — показать, что лежит в курируемых списках

```bash
llmbroker list
```

По модели на строку, и ничего не записывается. Строка `pool` — модель, по которой
пул роутит анонимно. Строка `direct` — платная модель, которую можно звать по
имени: сначала алиас, затем id провайдера, id модели, `base_url` и `api_key_ref`.

```
pool groq-gpt-oss-120b openai/gpt-oss-120b https://api.groq.com/openai/v1 GROQ_API_KEY
direct opus anthropic claude-opus-5 https://api.anthropic.com/v1 ANTHROPIC_API_KEY
```

Объявите алиас там, где создаёте брокер — `Broker(direct=["opus"])`, — и зовите
через `broker.direct("opus")`. См. [Прямые вызовы модели](direct.md).

## Чего CLI не делает

Команды, которая записывала бы список моделей, нет, и обновляющей его — тоже.
Модель, которую вы зовёте по имени, объявляется в вашем коде и нигде не
хранится. Брокер держит собственный список свежим сам
(см. [Использование](usage.md#sync)), а брокер на реестре в БД обновляет
его точка входа приложения вызовом `broker.sync("freetier")` — см.
[Серверы и кластеры](server.md#sync). Так конфигурация подключения и её секреты
остаются в одном месте, а слияние происходит там, где видны ключи, которые
приложение действительно разрешит: слияние, которое их не видит, сохранило бы все
записи.
