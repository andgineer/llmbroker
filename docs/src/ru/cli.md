# CLI

## preset — скачать готовый список LLM

```bash
llmbroker preset freetier > llms.toml
```

Доступные пресеты:

- `freetier` — бесплатные endpoints от Groq, OpenRouter и Gemini

## env — сформировать .env с ключами

```bash
llmbroker env llms.toml > .env   # из локального конфига
llmbroker env freetier > .env    # или сразу по имени пресета, без локального файла
```

Печатает заготовку `.env`: над каждым ключом — подсказка, где его получить:

```
# OPENROUTER_API_KEY — Create a free API key at [openrouter](https://openrouter.ai/keys).
OPENROUTER_API_KEY=
```

Аргумент — путь к конфигу, если такой файл есть; иначе имя пресета из каталога,
те же имена, что понимает `preset`.

Сами ключи получите у провайдеров и впишите. Брокер, созданный по пути к файлу
конфига, сам читает соседний `.env`; переменная окружения всегда важнее его.
Ключи вообще не обязаны лежать в `.env` — см. [API-ключи](secrets.md).

## preset --sync — обновить свой конфиг из пресета

```bash
llmbroker preset freetier --sync llms.toml
```

Переписывает в `llms.toml` модели пресета и подсказки к их ключам, сохраняет ваши
`[[custom]]`-записи вместе с их ключами и переводит каждую запись с `alias` на
то, что сейчас рекомендует платный каталог. Затем печатает отчёт о сделанном —
на каждом запуске, включая тот, где ничего не изменилось.

Модель, чьего провайдера пресет выбросил, удаляется только если у вас нет ключа
к этому провайдеру либо журнал рядом с вашим конфигом доказывает, что модель
мертва (401/403/404 и ни одного успеха). Иначе она остаётся и продолжает
маршрутизироваться. Поэтому обновление никогда не уменьшает число рабочих
моделей.

`--sync` принимает имя пресета и **файловую** цель. Цель-БД и файловый источник
отклоняются, каждый по своей причине:

- DSN дублировал бы конфигурацию подключения, которой уже владеет приложение, и
  требовал бы учётные данные БД в окружении CLI — а приложение, берущее DSN из
  Vault, их дать не может;
- рендер произвольного источника в живой `.toml` дублирует его
  `[[custom]]`-блоки и оставляет файл, который брокер не сможет разобрать.

Заливайте пул в реестр из своей точки входа: см.
[Серверы и кластеры](server.md#sync).

**Что видит CLI.** Ключи приходят из окружения и из `.env` рядом с целевым
файлом — ровно та же пара, которую разрешает файловый брокер, — а доказательства
смерти из каталога `store/` рядом с ним, если он есть. Поэтому конфиг, ключи
которого живут в Vault, AWS или базе, обновляется вызовом
`broker.sync("freetier")` из приложения: только приложение видит эти ключи, а CLI,
который их не видит, сохранил бы все записи.

Незаполненный ключ или оставленная запись — нормальное состояние, код выхода 0;
ненулевой код только при настоящей ошибке (каталог недоступен, в объединённом
файле оказались бы две записи с одним именем, каталога назначения не существует).
