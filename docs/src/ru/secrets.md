# API-ключи

В конфигурации каждой модели указано имя API-ключа. Источник значения зависит от
настроенного хранилища секретов. По умолчанию используются переменные окружения и
файл `.env`. Команда [`llmbroker env`](cli.md#env) создаёт заготовку с нужными
именами переменных и ссылками для получения ключей.

Подсказки доступны и из программы. Для каждого отсутствующего ключа поле `help`
есть в [состоянии пула](monitoring.md#pool-health) и в
[отчёте об обновлении](usage.md#sync). На их основе можно показать пользователю,
какие ключи требуются, без отдельного справочника провайдеров.

Модель без ключа не используется. Остальные модели продолжают работать. Это
правило одинаково для всех перечисленных ниже источников.

## Окружение и `.env`

Если отдельное хранилище не настроено, брокер сначала читает переменные окружения,
а затем файл `.env` из рабочего каталога. Значение из переменной окружения имеет
приоритет. Отсутствие файла не считается ошибкой. Файл разбирается средствами
стандартной библиотеки: поддерживаются строки `KEY=VALUE` и комментарии `#`, но
не подстановка переменных. Другой путь можно указать явно:
`secrets=llmbroker.Secrets("/etc/llmbroker.env")`.

## Ключи из кода

```python
secrets = llmbroker.DictSecrets({"GROQ_API_KEY": "gsk_..."})
```

В параметр `secrets=` также можно передать обычную синхронную или асинхронную
функцию вида `(имя) -> значение`. Так можно подключить собственное хранилище.

## AWS Secrets Manager

Установите дополнительные зависимости `llmbroker[aws]` (см.
[Установка](installation.md)):

```python
from llmbroker.aws import Secrets as AwsSecrets

async with llmbroker.AsyncBroker(
    "postgresql://host/db",
    secrets=AwsSecrets(region_name="us-east-1"),
) as broker:
    reply = await broker.ask("Привет")
```

По умолчанию используются имена вида `llmbroker/{имя ключа}`. Префикс можно
изменить в настройках.

## HashiCorp Vault {#vault}

Установите дополнительные зависимости `llmbroker[vault]`:

```python
from llmbroker.vault import Secrets as VaultSecrets

secrets = VaultSecrets(url="https://vault.example.com", token="s.xxx")
```

Используется KV v2 и путь `llmbroker/{имя ключа}`. Точка монтирования задаётся
параметром `mount_point=`.

Для [пользовательских ключей](server.md#multiuser) действует дополнительное
правило. В Vault символ `/` разделяет каталоги, поэтому имя
`u-42/GROQ_API_KEY` сохраняется в одном сегменте как
`u-42__GROQ_API_KEY`. Это различие видно только при непосредственном просмотре
Vault. Имена ключей и областей, уже содержащие `__`, не поддерживаются: их нужно
переименовать.

## Ключи в базе данных

Брокер, созданный с подключением к базе данных (`Broker("broker.db")`, PostgreSQL
или MongoDB), по умолчанию хранит ключи в той же базе. Подробнее см. в разделе
[Серверы и кластеры](server.md#datasource). Источник ключей можно задать отдельно:

```python
# база данных для моделей и журнала, переменные окружения для ключей
llmbroker.AsyncBroker("postgresql://host/db", secrets=llmbroker.Secrets())
```

## Свой ключ на пользователя

В многопользовательском приложении брокер сначала ищет ключ для текущего
пользователя, а затем общий ключ. Пользовательский ключ хранится под именем
`<область>/<имя ключа>`, например `u-42/GROQ_API_KEY`. Объект, созданный через
`for_scope("u-42")`, использует этот ключ вместо общего. Подробнее об областях
данных см. в разделе [Многопользовательские приложения](server.md#multiuser).
