Асинхронные вызовы и потоковая выдача

AsyncBroker предоставляет асинхронный API. Broker использует тот же механизм, но предоставляет синхронные методы. При работе с AsyncBroker методы вызываются через await:

async with llmbroker.AsyncBroker() as broker:
    reply = await broker.ask("Привет")
    print(reply.text)

Для асинхронного цикла инструментов используйте await llmbroker.arun_tool_loop(...). Подробнее см. в разделе Инструменты и агенты.

Потоковая выдача

Потоковая выдача доступна только через асинхронный API. Метод stream() возвращает части текста по мере их поступления. Выбор модели и переход к другой модели при ошибке выполняются так же, как для обычного вызова:

stream = broker.stream("Напиши хокку про брокеров", operation="write")
async for delta in stream:
    print(delta, end="", flush=True)

print(stream.llm_name, stream.usage)   # имя модели и сведения об использовании
await stream.record_quality(0.9)       # оценить полученный ответ

stream(...) возвращает объект асинхронного итератора. После завершения ответа в его полях доступны имя модели и сведения об использовании.

До получения первой части текста брокер может перейти к другой модели. Это происходит, если провайдер вернул ошибку, ограничил число запросов или завершил ответ без текста и вызовов инструментов. После получения первой части сменить модель без замены уже показанного текста нельзя. Если ответ прерывается в этот момент, возникает StreamInterruptedError, а ранее полученные части остаются у приложения. Поведение при fastest_of > 1 описано в разделе Параллельная потоковая выдача.

Параллельная потоковая выдача

При fastest_of > 1 брокер одновременно обращается к нескольким моделям. Все они продолжают работу, пока одна не завершит полный ответ. Модель, которая первой вернула часть текста, не обязательно первой завершит генерацию. Поэтому брокер не прерывает остальные запросы после появления первого текста.

Части текста, полученные до завершения одного из ответов, считаются предварительными. Если первой завершит работу другая модель, возникнет StreamReplacementError. Поле replacement этого исключения содержит полный итоговый ответ. Приложение должно заменить им весь ранее показанный текст. Части ответов разных моделей не объединяются.

stream = broker.stream("Напиши хайку", fastest_of=2, stream_selection_window=1.0)
parts = []
try:
    async for delta in stream:
        parts.append(delta)
        show(delta)
except llmbroker.StreamReplacementError as exc:
    replace_everything_with(exc.replacement.text)   # заменить предварительный текст
else:
    text = "".join(parts)

print(stream.llm_name)             # модель, чей ответ выбран итоговым
await stream.record_quality(0.9)   # оценить итоговый ответ

Оценивайте параллельный вызов через объект stream или exc.replacement. При fastest_of в журнале могут остаться несколько успешных попыток с одним trace_id, хотя пользователь получил только один ответ. Вызов record_quality(..., trace_id=...) не позволяет определить, какой именно ответ был показан. Поэтому используйте возвращённый объект или сохраните его call_id.

После StreamReplacementError итератор завершён и больше не возвращает данные. Обрабатывайте это исключение до более общего LLMRequestError, иначе готовый ответ будет ошибочно обработан как сбой.

Параметр stream_selection_window влияет только на выбор текста, который будет показан первым. В течение указанного числа секунд, по умолчанию одной секунды, брокер ждёт данные от модели, стоящей первой в текущей очереди. Если она не начала отвечать, показываются уже полученные данные другой модели. При ошибке первой модели ожидание прекращается сразу. Значение 0 означает, что нужно показывать первый поступивший текст независимо от порядка моделей.

Истечение stream_selection_window не считается ошибкой или превышением времени ожидания и не влияет на дальнейший порядок моделей. Итоговым остаётся полный ответ модели, которая завершила работу первой.

Каждый параллельный запрос расходует квоту провайдера, а его ответ хранится в памяти до выбора результата. Это происходит независимо от скорости, с которой приложение читает данные. Если одна модель прервёт генерацию или не успеет завершить ответ за время wait, брокер сможет использовать полный ответ другой модели. StreamInterruptedError или LLMTimeoutError передаётся приложению, только если ни одна модель не завершила ответ.

Если fastest_of не задан или равен 1, брокер после получения первой части текста продолжает работать только с этой моделью, а stream_selection_window не влияет на поведение.

Ограничение времени для полного ответа

wait ограничивает время получения полного ответа, а не только первой части. Учитывается только время, которое библиотека ждёт данные от провайдера:

stream = broker.stream("Напиши длинный ответ", wait=20.0)
try:
    async for delta in stream:
        print(delta, end="", flush=True)
except llmbroker.LLMTimeoutError as exc:
    print(f"\nвремя ожидания истекло: {exc}")

Время, которое приложение тратит на обработку уже полученной части, не учитывается. Отсчёт приостанавливается при передаче данных приложению и продолжается при запросе следующей части. Если модель быстро начала ответ, но генерирует его слишком медленно, ограничение всё равно сработает.

Если wait не задан, пользовательского ограничения времени нет. Если время истекло до получения первой части, возникает NoLLMAvailableError; после первой части возникает LLMTimeoutError, а ранее полученные данные остаются у приложения.

Модель, которая не вернула никаких данных за время wait, временно исключается из выбора. Если модель уже начала отвечать, временная блокировка не применяется. В обоих случаях брокер учитывает, какое значение wait оказалось недостаточным, и в следующий раз предпочитает другую модель для такого же короткого запроса. Незавершённый ответ нельзя оценить: при вызове record_quality у его объекта возникнет исключение.

До получения первой части поля llm_name и call_id равны None, поскольку брокер ещё может перейти к другой модели. Поле usage заполняется после завершения ответа.

Оценку также можно записать только после завершения ответа и появления записи в журнале. При более раннем вызове record_quality возникнет ValueError.

Чтение можно прервать в любой момент, но break не закрывает итератор и не освобождает место для следующего запроса. Без явного закрытия это произойдёт только при сборке мусора. Вызовите aclose() самостоятельно. Закрытие завершает вызов и позволяет оценить уже полученную часть ответа:

stream = broker.stream("Напиши хокку про брокеров")
async for delta in stream:
    if looks_wrong(delta):
        break

await stream.aclose()
await stream.record_quality(0.0)

Если сохранять оценку не нужно, для гарантированного закрытия можно использовать контекстный менеджер:

async with contextlib.aclosing(broker.stream("...")) as stream:
    async for delta in stream:
        ...

Потоковая выдача доступна и для одной конкретной модели через direct(), без выбора из пула и перехода к другой модели. Подробнее см. в разделе Прямые вызовы модели.

Локальная база данных для одного процесса

SQLite хранит модели, ключи и журнал в одном файле. Этого достаточно для приложения с одним процессом. Поддерживаемый список моделей записывается в базу перед первым вызовом:

async with llmbroker.AsyncBroker("broker.db") as broker:
    print((await broker.ask("Привет")).text)

Пустая база заполняется автоматически до создания пула; отдельный шаг инициализации не нужен. В дальнейшем список также обновляется автоматически. Если удалённый каталог недоступен, брокер записывает предупреждение в журнал и использует данные из базы. Если база пуста, используется копия списка из установленного пакета.

Если приложение использует тот же файл, учтите режим WAL и блокировку файла. Подробнее см. в разделе SQLite: общая база и WAL. Для нескольких процессов или серверов обновляйте базу один раз во время развёртывания приложения — см. Серверы и кластеры.
